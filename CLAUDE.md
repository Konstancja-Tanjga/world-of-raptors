@AGENTS.md

## Project

World of Raptors is a private, single-user online course about birds of prey (biology and field identification, focused on Poland, southern Spain and the Strait of Gibraltar). The owner writes and reads in Polish: all course content and UI copy are Polish; code, comments and commit messages are English; PR descriptions are Polish. Deployed on Vercel from `main` (https://world-of-raptors.vercel.app). Human-facing docs: `README.md`, `TECH.md` (Polish, how to add content), `content/PLAN-KURSU.md` (course plan), `DS-GAPS.md` (design-system gaps).

## Commands

```bash
npm run dev          # http://localhost:3000
npm run build        # production build; prerenders every lesson and species page
npm run lint         # eslint
npm test             # node --test over src/lib/*.test.ts (storage migration, backups, patches); no extra packages
npx tsc --noEmit     # type-check
python3 scripts/commons.py search "<query>" --out <dir> --limit 8   # find freely licensed Commons photos (downloads previews to inspect)
python3 scripts/commons.py tag "File:<title>" --podpis "…" --alt "…" # print a <zdjecie> tag with author/licence filled in
python3 scripts/commons.py rozmiary  # record each Commons photo's original size in content/zdjecia.json
python3 scripts/nazwy.py            # species names in other languages from Wikidata → content/nazwy-gatunkow.json
```

The tests cover the pure rules in `src/lib` and the accounts migrations, which `supabase/tests/konta.test.mts` runs on PGlite (`npm test`: Node strips the types, `scripts/testy/rozwiaz.mjs` resolves extensionless and `@/` imports, so avoid enums, namespaces and constructor parameter properties there). Verify changes with `tsc`, `lint`, `npm test` and `npm run build` (the build fails on malformed content: when `src/lib/content.ts` is imported, the cue keys, the eight-groups table, the module hooks and the modules' constellations stop at the first problem where they are read; `sprawdzSpojnosc()` then reports all its own problems together: species fields and look-alikes, silhouettes and flight styles, body lengths (`dlugosc_cm`, below the wingspan) and the reference birds of `miarka.json`, the photos' `fokus`/`oryginal` (and the third photo's `podpis`/`alt`), the birds of marshes (ids unique across both files, fields, group, `cechy`, `miejsca`) and the Marismas group sizes, module openings, the modules and lesson the code links to by name, the curiosities' lessons and species, the species drawn by name (`src/lib/rysunki.ts`, the constellations, the patches), and "Moje niebo": every species taught or named by some lesson, room on its map for every module, and every patch and gold star earnable once everything is done, with nothing earned from an empty start), then check the page in a browser.

Environment caveats:
- The repo lives in `~/Documents`, which iCloud syncs. iCloud creates `* 2.*` conflict copies (even inside `.git/`, and `.next 2` folders in the repo root) and has reverted a file to an older version. Before committing, look for `* 2*` files, compare them with the original and delete them; if `next build` fails with `ENOTEMPTY` on `.next`, `rm -rf .next.nosync/.next` (not `.next` itself, which is the symlink).
- Don't run two `next build`s against the same `.next` at once (parallel agents corrupt it).
- `node_modules` and `.next` are symlinks into `node_modules.nosync/` and `.next.nosync/`, because iCloud skips names ending in `.nosync`. Inside iCloud, reads of `node_modules` hung for minutes and iCloud deleted files from it. Both `npm install` and `npm ci` replace the symlink with a real folder, so after every install run `[ -L node_modules ] || { rm -rf node_modules.nosync/node_modules && mv node_modules node_modules.nosync/ && ln -s node_modules.nosync/node_modules node_modules; }`.

## Architecture

**Content is data, the app is a renderer.** Nearly all course material lives in `content/`:
- `moduly.json` defines the two paths, the modules (A1–A9, A13, B1–B7) and each module's lesson order and titles. A lesson exists for the app only if it is listed here, and a module only if it has `gotowy: true`, a `slug` and a `lekcje` list (`gotoweModuly` in `content.ts`).
- `moduly/<slug>/README.md` (module overview) and `moduly/<slug>/NN-*.md` (lessons). Routes `/moduly/[slug]` and `/moduly/[slug]/[lekcja]` are generated from `moduly.json` via `generateStaticParams` with `dynamicParams = false`.
- `gatunki.json` is the raptor atlas: Polish/Latin/English/Spanish names, `regiony`, `miejsca` (field-list sites), `aktywnosc` (`dzienny` | `nocny`), `mylona_z` (look-alike ids), `rozpietosc_cm` and `dlugosc_cm` (wingspan and body length, approximate; the lengths from the Collins Bird Guide) and `sylwetka` (ID cues). `miarka.json` holds B7's reference birds (sparrow to stork), which are not raptors and stay out of the atlas. Diurnal and nocturnal species use different `sylwetka` keys; the build throws if a species has unknown or missing keys. The cue order in `SpeciesCues.tsx` mirrors the method lessons (B1 for raptors, B5 for owls).
- `zdjecia.json` holds two reference photos per raptor (one, `siedzacy`, per bird of marshes) (Commons thumbnails with author and licence), plus an optional third, `cecha`: the view that most helps identification and the other two do not show (the other sex, a juvenile, a colour morph, a field mark), with its own `podpis` and `alt`. The species page and the lesson plates show it as a third photo. Each Commons photo also has `oryginal` (the original's size, filled by `commons.py rozmiary`, so `srcSetCommons()` only asks Commons for thumbnail widths that exist: 960, 1280, 1920, 3840); every photo has `fokus` ([x, y] in percent: a perched bird's head, a flying bird's middle). Every crop uses `fokus` as `object-position` (`polozenie()` in `src/lib/zdjecia.ts`), so a new photo needs one or its bird may lose its head. `ciekawostki.json` holds the rotating curiosities.
- Some pages quote the content, so its shape is load-bearing (the build checks each): the home page shows the "## Osiem grup" table of B1 lesson 1 and that lesson's lead (`grupySylwetek()`); every ready module's README needs a hook, its first `> ` block (written under the title), which the home page, the plan and the module's opening show (the overview drops the title, that block and the "Ścieżka X:" line); `/o-projekcie` needs "## Idea" in `PLAN-KURSU.md`; a new module needs a line in `OTWARCIA_MODULOW` (the species and photo its opening shows) and one in `GWIAZDOZBIORY` (`gwiazdozbiory.ts`: the bird and name of the constellation it lights).

**Birds of marshes ("Ptaki mokradeł").** Birds of marshes are the species of a site's field list that are not raptors. They live in `content/ptaki-mokradel.json` (`PtakMokradel` in `types.ts`), never in `gatunki.json`: they have no silhouette, flashcards, rings or scale. Each one is listed by a site (`miejsca`, labels in `MIEJSCA`). A raptor already in the atlas only gets the site added to its `miejsca`. The atlas and the checklist list both kinds through `ptakiNaLiscie` (`kategoria: 'drapiezne' | 'ptaki-mokradel'`); raptors are the default, and birds of marshes appear with the "Ptaki" filter (`?ptaki=mokradla`) or a site filter (`?miejsce=marismas-barbate`), in the photo view only, with a simpler species page (`PtakMokradelStrona`). `listaMiejsca()` gives a site's field list by group (`GrupaListyMiejsca`); the build checks the Marismas group sizes (8/1/5/14/4/2/9), which B6's text and patches rely on. Ids must be unique across both files, because the checklist keeps both under one key. `todo` fields (things to check by hand) are listed by `next dev`. The life list and its patches count raptors only; the Marismas patches count the field list.

`src/lib/content.ts` (server-only) loads all of this and is the single entry point for pages. Besides the module routes, the app has `/gatunki` (atlas) and `/gatunki/[id]`, `/checklista`, `/kiedy-jechac` (the trip planner), `/fiszki`, `/test-startowy` (Moduł 0, see below), `/plan`, `/moje-niebo` (achievements) and `/o-projekcie` (the About page with the credits). A species page links to the modules that cover it via `modulyGatunku()`, which maps `regiony`/`aktywnosc` and `miejsca` (`MODUL_MIEJSCA`) to hard-coded module slugs; a new region, site or module needs a line there (a bird of marshes links through `modulyMiejsc()`).

**Lesson rendering** (`src/components/Markdown.tsx`): `react-markdown` + `remark-gfm` + `rehype-raw` (raw HTML is allowed because content is authored in-repo). Relative `.md` links are mapped to app routes by `src/lib/links.ts`. Custom block tags: `<species-photos data-id="…">`, `<zdjecie src=… autor=… licencja=…>`, `<galeria>`, `<glos data-id="…">`, `<model-3d data-scena="…">` and `<quiz-krokowy>` (inserted by code, see below), and B7's drawings and exercises (`<miarka>`, `<anatomia>`, `<morf-grup>`, `<suwak-morfu>`, `<ptasia-miarka>`, `<zgadnij-sylwetke>`, read and checked on the server, so a wrong id stops the build) must be written with the opening tag on its own line and the closing tag on the next, with blank lines around them; otherwise Markdown wraps them in a `<p>`.

**Lesson pages are Big Hat `Article`s.** `przygotujStroneLekcji()` in `content.ts` turns a lesson file into the page: the `#` title is dropped (the title comes from `moduly.json`), a single paragraph right under it becomes the lead, the `##` headings become the table of contents (ids from `src/lib/naglowki.ts`, shared with the renderer, so `##` headings must stay plain text), and reading time is counted from the words.
- **Margin convention:** photos and side notes (`> ` callouts) go in `<margines>`, written *before* the paragraph they belong to, with blank lines inside so the content stays Markdown. It renders as `ArticleMargin`: beside the paragraph on a wide article, above it on a narrow one. Every `h2` clears the margin, so notes never drift into the next section.
- **Recordings:** `<glos data-id="puszczyk/samiec">` plays an entry of `content/nagrania.json` (`NagranieLekcji`: the species, what is heard, and the `Nagranie` credit) through `Nagranie.tsx`, which the starting test shares (there the sources wait for the answer). A recording is a Commons file (most are xeno-canto mirrors; an Ogg or WAV is played through Commons' MP3 transcode) or, when Commons has none, a freely licensed xeno-canto file converted to MP3 in `public/nagrania/` with its xeno-canto page as `strona`. `python3 scripts/commons.py nagranie "File:…" --gatunek … --lat … --opis …` prints an entry and refuses a file whose description, categories or title do not name the species. `problemyNagrania()` (`src/lib/nagrania.ts`) stops the build on a species not in the atlas, a host or licence not allowed, or a mirror titled with another binomial; `problemyTagow()` on a `<glos>` naming no entry. Every entry starts `zatwierdzone: false` until the owner has listened to it; `next dev` lists those. `scripts/sonogramy.py` (ffmpeg) draws each recording's sonogram, its first 12 s up to 4 kHz or, for low-voiced owls, 2 kHz, into `public/sonogramy/<gatunek>-<opis>.png` and records `sonogram: { khz, zrodlo }`: `khz` labels the scale under the player, and the build checks the file exists and that `zrodlo` is still the entry's `src` (a swapped recording must be redrawn).
- **Width and galleries:** the margin column widens from Big Hat's 13rem to up to 20rem with the room the article has beyond the text's measure (`--bh-article-margin` on `.lekcja .bh-article__grid`, the one custom property the product sets on a bh-* class; `DS-GAPS.md`), and the lesson page is centred. `<galeria>` (one to six `<zdjecie>`, nothing else) and species plates span the text and the margin (`margin-right` read from Article's variables) below the margin notes before them. Every `Photo` but the look-alike thumbnails is a button that opens `PodgladZdjec` (a native `<dialog>`), full screen and uncropped, so a page that shows a `Photo` must mount it (the lesson, module, species and plan pages do), and `Photo` throws at build on a photo the viewer would refuse; photos in one `[data-galeria]` (a gallery, a margin, a plate) step through with the arrows. Commons `<zdjecie>` tags carry `oryginal="WxH"` (`commons.py tag` writes it, `commons.py rozmiary-lekcji` fills every lesson), so a thumbnail whose original is at least 1280 px wide gets a `srcset`, with `sizes` for its place (`rozmiaryZdjecia()` in `podglad.ts`; a photo outside a gallery is taken to be in the margin). `problemyTagow()` (`src/lib/tagi.ts`, run by `sprawdzSpojnosc()` on every ready module's lessons and README) stops the build on a photo from elsewhere than Commons or `/zdjecia/`; without alt, author, licence or size; from Commons without its file page, or a thumbnail without `oryginal`; a tag in capitals, split over lines or not on its own line; or a malformed gallery.
- **Quiz:** a `## … Quiz (próg zaliczenia: N%)` section with numbered questions, each followed by an indented `a) … b) … c) …` line with the correct option in **bold**, is parsed by `wyodrebnijQuiz()` and replaced with the step-by-step `QuizKrokowy` (one question per screen, feedback after each answer, pass mark N%). Passing marks the lesson finished. A question without exactly one bold option fails the build.
- On module and lesson pages a sticky module bar (`PasekModulu`) shows the module's lessons as numbered steps with their state; on lesson pages it also carries a reading-progress line (`animation-timeline: scroll(root)`, under `@supports`).

**3D models (A9 Budowa ptaka).** `<model-3d data-scena="…">` (a block tag like `<glos>`) shows a scene of `src/lib/budowa/sceny.ts` (pure, no three.js: each view's model, pickable parts, layers `zewnatrz | miesnie | narzady | worki | szkielet`, cut, camera, sliders, breathing steps) with its parts' names, Latin names and descriptions from `content/budowa-ptaka.json` (`scenaBudowy()` in `content.ts`; `problemyBudowy()` stops the build on a part, scene or step without text or a text no scene shows; `problemyTagow()` on an unknown scene). The models are built in code with three.js from simple solids: `ptak.ts` (a goshawk coming in to land, 1 unit = 10 cm, +z the head, +x the right side, built right and mirrored; the skeleton inside the muscles and organs, all inside the plumage), `mikro.ts` (a primary at three magnifications, a bird's and a mammal's humerus), helpers in `geometria.ts`, the breathing cycle in `modele.ts`; every part id a scene names must be drawn (`modele.test.ts`, which builds every model in Node). `Model3D.tsx` (loaded through `CwiczeniaLekcji`) renders the controls (Big Hat `Slider`, `Select`, `SegmentedControl`, `Checkbox`, `Button`), and imports the viewer `scena.ts` (WebGL, OrbitControls, picking, clipping) only when the model nears the screen; it draws on demand, never in an idle loop, and a missing WebGL shows an error `StateBlock` while the parts list keeps working. Every pointer action has a control (rotation slider, zoom buttons, the parts list), and the self-test (`sprawdzian`) asks by highlighting a part and offering four names. The 3D colours are the drawing of the scene; the highlight takes `--wor-akcent` from CSS.

**Species plates are attached by convention.** `przygotujLekcje()` in `content.ts` finds `### <Name> — *Genus species*` headings whose italic binomial matches an atlas species and inserts that species' plate (`SpeciesMedia`: photos, `CuesTable` comparison with look-alikes, links) at the end of that heading's section. It also collects every atlas binomial mentioned in the lesson for the closing `LessonMedia` section. The italic Latin name is therefore load-bearing: renaming or un-italicising it silently removes a plate, and changes which lessons earn that species' "Znam" ring and which species a module's gold star asks for (in a module without plates, every italic binomial counts).

**Per-browser state, no backend.** Everything personal lives in the browser:
- `src/lib/magazyn.ts` is a generic store, reaching storage only through an `AdapterMagazynu` (localStorage today; synchronous, so a synced backend sits behind it as a local copy and announces its writes through `nasluchuj`). Keys carry a version: a change of shape gets a new key and a `poprzednia: { klucz, migruj }`, which moves the old key forward on first read and leaves it as a copy (a failed migration goes to `:bad`). It is used by the checklist (`checklist.ts`, key `wor:checklista:v2`, migrated from v1; schema and rules in `obserwacje.ts`: `{ widziany, data?, miejsce?, notatka?, zmieniono }`, unticking keeps the entry with `widziany: false`, so always read it with `jestWidziany()`/`widziane()`, never `Boolean(lista[id])`; migrated entries carry `ZMIENIONO_NIEZNANE`, older than any real change), lesson progress (`postep.ts`, `wor:postep:v1`), flashcard schedules (`fiszki.ts`, `wor:fiszki:v1`), the dates achievements were earned (`zdobyte.ts`, `wor:odznaki:v1`) and the last lesson opened (`ostatnia.ts`, `wor:ostatnia:v1`, for "Kontynuuj"; a convenience, not in backups). Its hook returns `null` until the stored copy is read (always on the server and during hydration), so views of the data render a `StateBlock` loading state instead of a guessed value. Two deliberate exceptions: small progress marks (module rings, the bar's count, the home collection, a species page's rings, the night sky's constellations) render nothing until read, and the start buttons offer lesson 1, which is right for a first visit. Unreadable stored data is copied to `<key>:bad` before the store starts empty; saves return `false` when the browser refuses, and callers show a toast via `useOstrzezenieZapisu`.
- The trip planner (`/kiedy-jechac`, `PlanerWyjazdu.tsx`) is the only page that fetches data from elsewhere: ten days of tide (Open-Meteo Marine, 15-minute sea level) and weather (Open-Meteo) for the chosen site, in the browser on each visit, credited on the page (CC BY 4.0). Its rules are pure functions in `src/lib/planer.ts` (tested): in the Marismas, the rising tide from three hours before high water to one after, in daylight, scored by tide range, rain and wind, with a Levante bonus; at La Janda, 11:00–16:30, scored by rain and wind. Forecasts are fetched in UTC (`timezone=GMT`: with `Europe/Madrid`, Open-Meteo keeps the first day's offset for the whole range, so times after a clock change are an hour off) and counted in UTC minutes; only what is shown, and the dates of days, are Madrid wall-clock (`naMadryt()`). An incomplete forecast throws `NiepelnaPrognoza` and the page says the data is missing rather than planning on it. The model's tides run about half an hour ahead of the port tables, which the page says. The chosen site is a convenience store (`wor:planer:v1`), not in backups.
- The owner's own photos are in IndexedDB (`zdjeciaWlasne.ts`), re-encoded to max 1600 px JPEG, which also strips EXIF/GPS.
- Backups (`kopia.ts`, format v3: checklist (v2 shape) + progress + flashcards + earned dates + photos; `fiszki` and `odznaki` are optional because older files lack them; v1 and v2 files still import, their checklist moved forward by `checklistaZDowolnej`; a newer format is refused with its number). Import validates and decodes the whole file first, then writes photos in one aborting transaction, then progress and flashcards, then merges the earned dates (`wczytajZKopii`: the earlier date wins, and the next evaluation records without announcing), then the checklist. Keep that order.
- The curiosity card remembers what was already shown under `wor:ciekawostki:widziane`.
- The chosen sky is a cookie (`wor-pora`, a year), not `localStorage`, because the server renders the home page with it. The server sets it (`POST /pora-nieba`, `src/app/pora-nieba/route.ts`), since Safari caps cookies written from script at seven days.

**The starting test** (`/test-startowy`, Moduł 0 of `PLAN-KURSU.md`): fifteen fixed questions in `content/test-startowy.json` (silhouettes, photos, sounds, knowledge), the same at the start and the end of the course. `testStartowy()` in `content.ts` builds and checks them at import, so the build stops on a missing species, photo, silhouette, B1 group or quiz question; knowledge questions point at a lesson quiz (`zrodlo`: `modul/lekcja#n`) rather than copying it, and name the lesson that teaches the topic (`lekcja`), which the answer links to. Sounds are Commons files from xeno-canto; `zatwierdzone` is set once the owner has listened (Claude cannot), and the species named in the file must be the one recorded (`Genus:`/`Species:` in the Commons description; a search by genus once returned a North American Broad-winged Hawk as a Common Buzzard). As on flashcards, nothing on the question side names the answer: the Commons and xeno-canto links wait for it. Scoring and the suggested starting module per path are pure (`wynikTestu.ts`); the first and the latest result live in `wor:test-startowy:v1` (not synced or backed up yet).

**Flashcards** (`/fiszki`, `FiszkiView.tsx`): `taliaFiszek()` in `content.ts` builds three kinds of card, ids `<species>/<rodzaj>`: photos (`lot`, `siedzacy`; these ids predate the others, so stored schedules carry over), silhouettes (`sylwetka`, diurnal species with a shape) and names (`pl-en`, `pl-es`, `en-pl`, `es-pl`). A fourth kind, the "Budowa ptaka" deck (`taliaBudowy()`, ids `budowa:<part>/czesc-obraz|czesc-nazwa`, `FiszkaBudowy` in `types.ts`), asks two cards per part of A9's models (the lit part on a picture of the model → its name; the name → where it lies and what it does), each linking to the lesson that shows it; the pictures are `public/budowa/<part>.jpg`, drawn from the running app by `scripts/budowa-obrazy.mjs` (redraw after changing a model; the build stops on a missing one, `BUDOWA_BEZ_OBRAZOW=1` lets one build through to run the app the script draws from). These cards have no region and count towards no achievement. All are scheduled by FSRS (`ts-fsrs`, default parameters with fuzz). A card with no stored entry is new. Order: overdue reviews, then new cards (up to 10 a day, counted by `wprowadzona`; the empty state's button adds 10 more for the visit), then reviews due within the next 20 minutes. As in Anki, a new card waits until tomorrow when a card of the same species was answered today. The question side gives nothing away: photo and silhouette cards name nothing (alt text included), and a photo credit's Commons link, whose file name usually names the species, waits for the answer; a name card shows only the name it asks to translate. The store (`fiszki.ts`) imports only types from `ts-fsrs`; the scheduler is `planFiszek.ts`, so pages that only read schedules (Moje niebo and its watcher) do not load it.

**Moje niebo** (`/moje-niebo`, `src/components/niebo/`) is a collection computed from the stores above; it locks nothing. `src/lib/odznaki.ts` (no directive, no browser APIs: the build runs it too) holds the rules: a species earns three rings, `znam` (a finished lesson that teaches it: one with its plate, or, if none has one, one naming it), `rozpoznaje` (every flashcard of it learned: FSRS Review with `scheduled_days` ≥ 7, last answered on a later day than the first, so one lucky "Od razu" does not count) and the gold `widzialam` (ticked on the checklist); a module lights its constellation when all its lessons are finished and, once finished, earns a gold star when its species are recognised too (those with plates in it, else those its lessons name in italics; B1 asks for the eight group birds); nineteen `NASZYWKI` (patches) reward skills and the Marismas field list (a patch shows its birds or an `emblemat`: tide, wader tracks, a colour-ringed leg). Module slugs and patch ids are stored keys: never rename them. `strukturaNieba()` in `content.ts` works out which lessons teach which species and what each module asks for (the build stops on a species no lesson teaches or names); `gwiazdozbioryKursu()` gives each module's constellation, a bird from `GWIAZDOZBIORY` (`gwiazdozbiory.ts`) whose stars are the corners of its silhouette (`gwiazdy()` in `sylwetka.ts`). Earned stays earned: `zdobyte.ts` keeps the date each constellation, gold star and patch was first earned and whether its moment has played. `StraznikOdznak` (loaded lazily by `AppFrame` behind an error boundary, so on every page and never able to break one) records new ones and announces them in a toast; the first evaluation (no `start` key, and again after a backup is loaded) records without announcing. These writes are bookkeeping: they re-read the stored copy first (`odczytajAktualne()` in `magazyn.ts`, since another tab may have saved), only add, and are not warned about when refused. The page records what is earned too, then plays each unplayed moment once, when it scrolls into view (`moment.ts`), so the first visit reveals everything earned so far. At night the home sky draws the lit constellations in the part of the sky the text leaves free, clear of the moon (`ukladNaNiebie()`; the moon's place is `--ksiezyc-*` in `start.css`). Seen species are gold: `--wor-lifer` for drawings on paper (the atlas's group plates, the checklist, the home collection, the life list), `--wor-zloto` under text and on the scale view's sky.

**Accounts (Supabase), behind `NEXT_PUBLIC_ACCOUNTS_ENABLED`** (plan and phases in `KONTA.md`). The course works signed out; an account adds syncing. `src/lib/konto.ts` holds the one browser Supabase client and `useKonto()`; Google's own button (`PrzyciskGoogle`, Google Identity Services) signs in from the course's page and passes the ID token, with a nonce, to `signInWithIdToken`, so Google's consent screen names the course, not the Supabase project. The session lives in `localStorage` (`wor:konto`), so pages stay static: no `@supabase/ssr`, cookies or `proxy.ts`. `/konto` is a 404 while the flag is off. The schema is `supabase/migrations/`: one table per synced store (`lesson_progress`, `observations`, `flashcards`, `user_badges`), RLS on every table, soft deletes (`deleted_at`), and triggers that enforce the merge rules (the newer `updated_at`, the device's time of the change, wins, capped at five minutes ahead of the server; achievements keep the earliest date and `shown`), so clients may upsert blindly. `synced_at` is the server's time, which pulls page by. Keys are the stores' keys (`modul/lekcja`, species ids, card ids, achievement keys): never rename them. Env vars: `.env.example`. Syncing: `src/lib/synchronizacja.ts` (pure, tested on PGlite: per-table codecs from store entries to rows and back, and one pass: pull since the cursor, merge by the triggers' rules, send every entry whose fingerprint differs from `znane`, the version both sides last agreed on, kept per device in `wor:synchro:v1`); `synchronizacjaPrzegladarki.ts` joins it to the stores (each exports `…DoSynchronizacji`) and Supabase, and schedules passes (sign-in, a few seconds after a change, reconnect, every five minutes); `Synchronizacja.tsx` runs it, loaded lazily by `AppFrame` only when the flag is on (the flag is read inline there, so Supabase stays out of the shared bundle). Lesson progress keeps its change times and unticks in `wor:postep:slady:v1`; write progress only through `postep.ts`, which records them.

**Browser translation.** The course stays Polish; a browser can translate it (`<html lang="pl">`). Species names must not be translated word by word: `NazwaPtaka` renders a species' name as `translate="no"` text and, when the browser has translated the page (it sets `<html lang>` to the target language; `useJezykStrony()` in `src/lib/jezykStrony.ts` watches it), swaps in that language's name from the static `/nazwy-gatunkow` (English and Spanish from the atlas, the rest from Wikidata via `scripts/nazwy.py`, English when a language has none). It is fetched only once a page is translated. Latin binomials and English and Spanish names are plain `translate="no"`; in lesson Markdown `rehypeNazwy` does this for italic binomials, the name after "ang." and the Polish name in species headings (`### Kania czarna — *Milvus migrans*`). Polish names inside sentences are declined, so the translator handles those. Render a species' visible name with `NazwaPtaka`, not `{g.pl}`; strings (alt text, aria labels, titles) are left to the translator. `odpornoscNaTlumacza()` (installed in `AppFrame`) stops React's removeChild/insertBefore from throwing when the translator has replaced text nodes (react#11538).

**Rendering modes.** Every page is static except the home page (`export const dynamic = 'force-dynamic'`), which picks a species of the day by the Europe/Warsaw date and paints the sky for the sun's height over Warsaw (`src/lib/niebo.ts`). A time of day chosen in the scene's "Pora nieba" control, or arriving as `?pora=swit|dzien|zmierzch|noc` (the About page's links), is kept in the `wor-pora` cookie (`src/lib/poraNieba.ts`) until "Teraz" clears it; the server reads the cookie, so the first frame is already the chosen sky. Client-only choices (a random curiosity) are made after mount, because a server-side pick would freeze at build time. The card a shared link shows is `src/app/opengraph-image.tsx`, drawn once at build with `ImageResponse`: the dusk sky, a kettle of silhouettes from the engine below, the title and the author; its two fonts are fetched from Google Fonts as TrueType subsets (ImageResponse cannot read woff2), and `metadataBase` in `layout.tsx` sets its production address. Images use `images.unoptimized`: Commons thumbnails are served directly; `public/zdjecia/` holds resized copies of the owner's own photos. The originals sit in the git-ignored `/Images`; never publish or reference them directly.

**Silhouettes are numbers.** `src/lib/sylwetka.ts` draws a bird seen from below (raptors and owls) from a `Ksztalt` of 23 proportions (wing chord at the body and wrist, sweep, wingtip, number and depth of the fingers, tail length, fan and fork, head projection) in a `Poza` (wings raised, hand folded, tail fanned). `src/lib/sylwetki.ts` holds each species' numbers (`SYLWETKI`, built from archetypes of the B1 groups, the osprey a modified kite, plus one for owls), a resting pose where it differs from `POZA_SZYBOWANIE` (`POZY`: the red and black kites and the osprey) and each diurnal species' flight style (`STYL_LOTU`, `pozaWLocie()`). The same outline renders as static SVG (`Sylwetka.tsx`, `Miarka.tsx`, `PlanszaGatunku`, `Anatomia`) and animates in the browser (the home sky on canvas, `MorfGrup`, `ScenaSylwetki`, `SuwakMorfu`). Interpolating two shapes (`posredni`) is what morphs one bird into another. Every raptor needs an entry in `SYLWETKI`, and every diurnal one in `STYL_LOTU` (the build checks); birds of marshes have none. Only `AppFrame` is in every page's client bundle (plus the watcher's chunk, loaded after the page: the stores and the rules, no generator), so its logo arrives drawn on the server (`znak`); `ChecklistView` does the same (`sylwetki`), and so does `MojeNiebo` (`sylwetki`, the patches' `rysunki`, and the constellations' stars). The pages with animated or client-drawn silhouettes ship the generator anyway: the home page, the atlas, species pages, the flashcards and the About page, and the lessons with a `<morf-grup>` or `<suwak-morfu>` tag (`CwiczeniaLekcji.tsx` loads B7's client parts lazily, so other lessons do not). Species the code draws by name (the logo, the path guides, the home sky's birds, the share card's kettle) are listed in `src/lib/rysunki.ts`, which the build checks; the constellations' and patches' birds are in `gwiazdozbiory.ts` and `odznaki.ts`, checked the same way.

**The frame.** `AppFrame` is not Big Hat's `AppShell` (its contract excludes publication pages; see `DS-GAPS.md`): a skip link, the global navigation, the module bar, `<main id="main-content">` and the footer (`Stopka`, which carries the authorship).
- `Nawigacja` is translucent and turns light-on-dark while a `[data-scena]` element covers its middle line. A page whose first section is a scene pulled up under the bar (negative top margin of `--wor-nav-height`) must also be listed in `zaczynaSieScena`, so the bar starts dark before the observer runs. The bar sticks everywhere except module and lesson pages, where the module bar sticks instead. Below 1000 px (the links' width, the account link included) it has a menu sheet; `globals.css` and `Nawigacja.tsx` share the breakpoint.
- "Kontynuuj" (`cel()` in `kontynuuj.ts`) leads to the lesson opened last unless it is finished, then to the next unfinished one, wrapping round to the start; with no history and no progress it reads "Zacznij kurs". It is hidden on its own target, while progress loads and once every lesson is done (`stan`: `wczytywanie` | `ukonczony` | `lekcja`).
- Page transitions are a React `ViewTransition` keyed by the route; a species' name is a shared element between its atlas card or the species of the day and its page title (`nazwa-<id>`), so each name may appear only once per page.
- `error.tsx` (inside the frame) and `global-error.tsx` (when the root layout fails; it brings its own document and styles) show an error `StateBlock` with "Spróbuj ponownie".

## Big Hat design system

UI is built on Big Hat (`@bighat/ui`, installed from GitHub at a pinned commit, not from npm).
- Before writing UI, read `node_modules/@bighat/ui/agent/SKILL.md` and `react.md`. Component contracts are in `node_modules/@bighat/ui/spec/components/*.json`; check `notFor` before choosing a component.
- Import components from `@/components/ds` (a `'use client'` re-export, since the package has no directives), never from `@bighat/ui`. Components take no `className`/`style`; page layout classes live in `src/app/globals.css` and the page stylesheets (`start.css`, `gatunki/atlas.css`, `moduly/[slug]/modul.css`, `o-projekcie/o-projekcie.css`). They take colour, type (sizes, weights, leading), spacing, radii and motion timing from tokens; literals are allowed for `1px` borders, focus outlines, reading measures, breakpoints, backdrops stacked at z-index −1/−2 inside an isolated scene, and the choreography and drawing of a single scene (keyframe offsets, one-off durations, hover-lift distances, illustration and type-sample sizes).
- `src/app/motyw.css` is the product's theme in two layers: Big Hat's semantic `--bh-*` roles given this course's values ("Papier terenowy" light, "Zmierzch" dark, contrast-measured to WCAG AA in the browser, including text over photos and skies; re-measure after changing a colour or a shade), and a `--wor-*` layer for what Big Hat lacks: Półtawski Nowy and Newsreader (loaded by `next/font` in `layout.tsx`), display sizes and leading, expressive motion, sky gradients and scene colours. A `.scena` element gets the dark values in both modes. Safari (WebKit 26.5, October 2026) draws a stray row in an `in oklch` gradient whose hue crosses 0° (purple to rose): such a gradient is sampled into stops and blended `in oklab` (the dawn and dusk skies).
- Reduced motion: small motions (hover lifts, the menu, reveals) multiply their travel by `--wor-ruch`, which is 0 under `prefers-reduced-motion`, so they fade in place; entrances, scroll effects and flight scenes sit inside `@media (prefers-reduced-motion: no-preference)` and are skipped; page transitions become instant. Loops check the media query themselves, and each has a pause button whose label says what pressing it does (no `aria-pressed` on top).
- Empty, loading and error states are always `StateBlock`.
- `ButtonLink` is a local component: navigation styled with `bh-button` classes, because `Button`'s contract excludes navigation.
- `Card` holds one action at most (contract `notFor`: "Cards with two actions inside").
- When the system can't do something (e.g. its built-in uppercase labels, no type size above `display`), record it in `DS-GAPS.md` instead of overriding `bh-*` classes.
- Deliberate visual decisions: no emoji as icons, no arrows in button labels, no ALL-CAPS labels of our own, no " · " meta strings (module ids read like catalogue numbers with a non-breaking space: `B3 Cieśnina Gibraltarska`). Every motion should teach something about the birds. Scroll-linked effects run only under `@supports (animation-timeline: view())` and `no-preference`, and the base, un-animated styles show everything, so a browser without them gets the complete page without those effects (the opening entrances, the scenes and page transitions still move where motion is allowed). The one exception is the module bar's reading-progress line, which only exists where `scroll()` timelines do.

## Content conventions

- Polish throughout. The owner refers to herself in the feminine first person ("Ukończyłam tę lekcję", "Zaobserwowałam"); keep that form.
- Species on first mention: Polish name, *Latin binomial* in italics, `(ang. English Name)`.
- Facts are hedged ("ok.", "uważa się") when uncertain; don't state precise figures you can't source.
- Lesson photos come from Wikimedia Commons with free licences only. Verify each photo visually and check that the file title names the right species (past mistakes: a Bald Eagle filed as White-tailed Eagle, *Circus hudsonius* as Hen Harrier, a Tawny Eagle as Short-toed Eagle).
- Curiosities (`ciekawostki.json`) must stand alone: bold/italic only, no links (the block's way on is "Czytaj dalej").
